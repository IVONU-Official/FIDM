# Security policy

FIDM is an early prototype. Do not use it for sensitive downloads until the project has a published security release process.

## Reporting a vulnerability

Do not publish exploitable vulnerability details in a public issue. Use GitHub's private vulnerability reporting feature for the FIDM repository when it is enabled. If private reporting is unavailable, contact the repository owner privately through GitHub and include steps to reproduce, affected versions, and potential impact.

The maintainers will acknowledge reports when practical, investigate the affected code, and coordinate disclosure after a fix is available.
